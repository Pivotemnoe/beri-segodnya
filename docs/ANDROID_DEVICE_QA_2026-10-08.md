# Проверка Android на телефоне — 8 октября 2026

## Результат

Основной учебный сценарий прошёл на физическом TECNO CAMON 19 (CI6n), Android 13. Это была проверка установленного подписанного APK, а не обычной вкладки браузера. Приложение работает через доверенную TWA сайта: экран обслуживает Chrome внутри задачи приложения, без адресной строки браузера.

Клиент выбирает предложение и получает код. Владелец заведения может войти в партнёрский кабинет, добавить предложение и фото. Продавец может найти код и отметить выдачу, но не публиковать предложения. Все эти действия доступны внутри одного APK; отдельного приложения для партнёров сейчас нет.

- APK: `0.1.0-pilot`, version code `1`, package `ru.berisegodnya.app`.
- SHA-256 APK: `ce94ec4bcbb0727f643e3419e9dcc5e840bc11937c0b1af1a493ba03f45f63e8`.
- Подписи v2/v3 и совпадение сертификата с Digital Asset Links проверены повторно; домен Android — `verified`.
- Исправления сайта: релиз `2ea1e8f672cb3ff9540373c162f9f8b50b853e7c`, [PR #20](https://github.com/Pivotemnoe/beri-segodnya/pull/20).
- Пересобирать APK для этих веб-исправлений не потребовалось. Эмулятор и Android SDK на Mac не скачивались.

## Что исправили

1. При посимвольном вводе номера с `8` маска сохраняла лишнюю восьмёрку. Теперь ввод `89001234567` превращается в `+7 (900) 123-45-67`.
2. Удаление телефона останавливалось на закрывающей скобке. Теперь Backspace проходит через разделители, а код `+7` остаётся.
3. Выбор готового фото принудительно открывал камеру. Теперь есть отдельные действия «Сделать фото» и «Выбрать фото». Готовый файл можно загрузить без разрешения на камеру; обработка фото и общий лимит три фотографии сохранены.

Для этих ошибок добавлены регрессионные проверки. Проверки сборки, безопасности, API, границ HTTP-запросов, квот загрузки и резервного копирования прошли на изолированном хранилище. Оба CI-задания PR #20 завершились успешно. На сервере сверены 209 файлов релиза, резервные копии, APK, настройки и состояние единственного процесса приложения.

## Что осталось после теста

- Учебное предложение скрыто с витрины, заведение перенесено в архив, оба учебных аккаунта отключены.
- Сверка прежних восьми партнёров, восьми предложений и четырёх броней подтвердила неизменность этих записей.
- Две учебные брони и журнал сохранены для проверки истории. Рабочая база не подменялась резервной копией.
- Пароль администратора заменён через штатную форму API: новый вход проверен, старый пароль отклоняется. Доступ сохранён в защищённом файле на Mac, не в Git и не в этом отчёте.
- Wi-Fi и мобильные данные восстановлены в исходное состояние. Временное удержание экрана включённым отменено, защищённая блокировка не менялась.
- Удалены только созданное нами фото и пустая учебная папка на телефоне; APK оставлен установленным.
- После очистки публичная витрина снова содержит ноль активных предложений, как до теста. Это не означает запуск с реальными заведениями.

## Что ещё нельзя считать проверенным

- Съёмка нового фото камерой: проверены отказ в разрешении и загрузка готового файла, но не нажатие затвора и возврат нового снимка.
- Слабая и прерывистая связь: проверено полное отключение и восстановление, не задержки и обрывы во время отправки.
- Настоящий холодный запуск веб-процесса: остановка только оболочки не завершает разделяемый процесс Chrome и не доказывает такой запуск.
- Другие Android-модели/версии, iPhone/PWA, доступность с экранным диктором и нагрузка реальной смены.
- Полная стоимость памяти и плавность веб-экрана: показатели маленькой оболочки нельзя выдавать за расход Chrome/TWA; полного профилирования не выполнялось.
- Юридическая готовность и реальные условия работы магазинов требуют отдельного подтверждения.

Поэтому результат — основной сценарий принят на одном Android. Утверждение «полностью проверено на всех устройствах и готово к публичному запуску» не делается.
